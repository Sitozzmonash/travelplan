# 引导式流程调整：首页与「基础信息」页重叠、酒店两个字段要删、排版要齐

> 记录时间：2026-09-21
> 来源：用户走 `/guided` 时的连续反馈
> 本文件只记录诉求与现状，不含实现。

## 一、首页与向导第 1 页几乎完全重叠 → 删掉第 1 页

对照当前字段（`frontend/app/page.tsx` 的 `HomeLaunchpad` vs `frontend/components/guided/step-basic.tsx`）：

| 字段 | 首页 | 向导第 1 页「基础信息」 |
| --- | :---: | :---: |
| 出发地 | ✅ | ✅ |
| 目的地 | ✅ | ✅ |
| 出发日期 | ✅ | ✅ |
| 玩几天 | ✅ | ✅ |
| 几个人 | ✅ | ✅ |
| 预算 | ❌ | ✅ |
| 行程长度模式（按天数 / 按返程日期） | ❌ | ✅ |

**6 项里 5 项重复**。用户从首页点「开始规划」进来，第一眼又是刚填过的一模一样的表单 —— 这正是"磨叽"的来源。

### 期望的流程

```
首页（填出发地/目的地/日期/天数/人数/预算）
  → 直接进「探索确认」（拿到 POI，用户勾选）
  → 再到「偏好」（机票 / 酒店 / 旅行节奏）
  → 开始规划
```

即：**向导里不再有独立的「基础信息」页**，向导第一页就是探索确认。

### 唯一需要安排去处的是「预算」

`预算` 和 `行程长度模式` 是第 1 页里唯一不重叠的两项，删页前必须给它们落点：

- 预算：按用户更早的口径（"第一个页面就填出发、目的地、预算、玩几天、几个人"）应当**补到首页**；
- 行程长度模式：首页现在只有"玩几天"一种输入，若要保留"按返程日期"，也得放到首页。

## 二、酒店这块删两个字段

要删：

- **「接受换酒店吗？」**（`frontend/components/guided/step-hotel.tsx:134`）
- **「最低星级」**（同上 `:90`）

删完后酒店页只剩三项：`酒店你更看重什么` / `每晚价格上限` / `房型`。

### 连带影响（不删干净会留死代码）

这两个字段在原实现里有一整套配套，删 UI 时必须一起收：

- 前端：`starFilterAvailable` / `allowChangeAvailable`（读 `session.capabilities.hotel_star_filter` / `hotel_allow_change`）、`dropStarFilter()` / `dropAllowChange()`（`guided-wizard.tsx`）、`hotelDetailLabels()` 的 `includeStar` / `includeAllowChange` 分支（`draft.ts`）—— 这些会全部变成不可达；
- 摘要卡里对应的展示行也要去掉，否则会出现"用户没选过却显示最低星级"的假信息；
- 后端若不消费这两个字段，`capabilities` 声明与 PATCH 白名单是否随之收敛，需要一起确认（**不要把"前端不发了"当成"后端不认了"**）。

## 三、排版尽量整齐

诉求是"整页看起来齐"，当前已能观察到的具体不齐点：

1. **偏好页三块的间距与栅格不一致**：`step-preferences.tsx` 用 `gap-7` 包三块，而 `StepTransport` / `StepHotel` 内部是 `grid gap-6`、`StepPace` 是 `grid gap-5` —— 三块自己的呼吸感不同，中间又插了我加的分隔线，观感偏松。
2. **酒店的栅格会变奇数**：删掉「最低星级」「接受换酒店吗」后，酒店那块的卡片数量从 5 变 3，原本两列/多列的排布会出现落单项。
3. **输入控件高度不统一**：`step-basic.tsx` 里「出发日期」是原生 date input、「按天数/按返程日期」是自绘分段按钮、「行程天数」又是文本框，同一行内三种高度。
4. 首页的 `LabelField` 与向导里的 `StepSection` 是两套排版语言，同一个"出发地"在首页和向导里长得不一样。

（第 4 条会随着"删掉基础信息页"自然消失，前三条仍需单独处理。）
