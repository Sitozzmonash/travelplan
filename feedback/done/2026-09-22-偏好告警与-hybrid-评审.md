# 偏好告警与 Hybrid Agent 化评审（2026-09-22）

## 问题描述

管理后台的 `user_preference_ignored` Bad Case 会调用 `app/badcase.py::_applied_selection_ratio`。原实现即使读出了 `journey.selected_ids`，也没有使用它；只要最终计划存在任意一个带 `place_id` 的项目，就返回 `1.0`。因此用户选中的 MUST/WANT 地点全部未进入行程时，检测规则仍会认为选择已被采用，Dashboard 的对应告警不会出现。

同时，`_user_journey_summary` 以前只保存 MUST/WANT/REJECT 的数量，没有保存可与 `plan.days[].items[].place_id` 对比的选择身份，无法可靠计算这个比例。

## 本次改动

- 在 `user_journey` 审计中写入 `selected_ids`：收集 MUST/WANT 的稳定地点 ID；兼容旧的名称键、已合并的旧 ID，并保留无法解析的选择键，避免选择未进入候选池时被静默丢失。
- 将 `_applied_selection_ratio` 改为 `planned ∩ selected_ids / selected_ids`；没有计划或计划为空时为 `0.0`，历史审计没有 `selected_ids` 时返回 `None`，不以数据不足制造误报。
- 增加 Guided 端到端回归：用户选择一个没有进入最终计划的 WANT 地点时，必须写入 `user_preference_ignored` Bad Case。

## Hybrid Agent 化结论

建议的取舍合理：`extract_places` 与 `critic` 适合在低置信度或证据缺失分支进入 SuperHarness 的工具循环；意图解析、画像、检索词、预算/可行性、候选打分、实体去重和成文仍保持现有 JSON/确定性路径。当前 API 固定走 `Route.WORKFLOW`，并且 `tests/test_workflow.py::test_the_model_is_only_consulted_at_the_documented_sites` 把六处模型调用点锁死；落地前需要先定义低置信度信号、单次最多工具调用数/时间预算，以及将该测试升级为“调用点白名单 + 工具白名单”。这些是独立的架构改动，本次未混入偏好告警的热修复。
