# TravelPlan 结果页前端：问题描述与优化建议

## 1. 当前问题概述

当前结果页功能已经比较完整，已经有：

```text
行程摘要
交通
酒店
预算
可信度
每日地图
每日时间线
美食
来源
可行性检查
修改入口
```

但目前页面的问题不是“功能不够”，而是：

> **信息太多、重复展示较多，主次不够明确，整体更像一份 AI 生成报告，而不是一个真正好用的旅行行程工作区。**

用户进入结果页后，最想马上知道的是：

```text
我这几天怎么玩？
今天去哪？
住哪里？
怎么走？
吃什么？
```

优化重点应该是：

```text
减少重复
突出 Day 行程
地图 + 时间线成为主角
技术信息下沉
```

## 2. 第一屏信息层级不够清晰

### 问题

当前页面顶部大致是：

```text
行程状态 / 行程编号
↓
行程摘要
↓
交通 / 酒店 / 预算 / 可信度 四张卡
↓
地图
↓
时间线
```

用户真正最关心的“每天怎么玩”出现得偏晚。

### 建议优化

第一屏改成：

```text
成都 · 3天2晚
9月25日 - 9月27日 · 2人 · 预算 ¥5000
偏好：美食 · 商圈 · 轻松

酒店：春熙路 XX酒店
交通：Gxxxx
预计花费：¥4280

Day 1 | Day 2 | Day 3
```

然后马上进入：

```text
地图 + 当天时间线
```

原则：

> **第一屏先回答“怎么玩”，再回答“为什么这么安排”。**

## 3. Day 切换位置不合理

### 问题

现在地图已经显示：

```text
Day 1 路线总览
```

但 `Day 1 / Day 2 / Day 3` 的切换按钮放在下面的“行程”卡里。

### 建议优化

把 Day Tabs 提到地图和时间线共同的最上层：

```text
Day 1 | Day 2 | Day 3
────────────────────
地图
+
当天行程
```

Day 切换应同时控制：

```text
地图
当天路线
当天时间线
今日美食
当天可行性
```

## 4. 地图不应该继续使用“示意地图”

### 问题

当前地图本质上是：

```text
SVG 示意图
+
真实经纬度点位投影
```

背景道路、河流并不是真实地图。

### 建议优化

最终接入真实高德地图：

```text
高德 JS SDK
真实道路
真实 POI
真实路线 Polyline
酒店位置
景点编号
餐厅位置
```

并支持：

```text
点击地图地点
→ 高亮 Timeline 对应项

点击 Timeline
→ 地图定位对应地点
```

## 5. 同一信息重复展示过多

### 问题

当前存在明显重复：

```text
酒店：顶部 Summary + 右侧详情
交通：顶部 Summary + 右侧详情
预算：顶部 Summary + 底部完整预算
美食：Timeline + 右侧今日美食
路线：动线摘要 + 地图 + Day Intent + Timeline
```

导致页面过长、信息密度高。

### 建议优化

统一规则：

> **顶部只展示短摘要，详细内容只完整出现一次。**

例如：

```text
酒店摘要：
春熙路 · XX酒店 · ¥420/晚

点击
→ 酒店详情 / 候选比较
```

交通、预算、美食同理。

## 6. 地图前后的当天总结重复

### 问题

现在同时有：

```text
今天的动线
A → B → C

地图

今天以 XX 区为主
3 个游览安排
2 顿当地用餐
移动约 50 分钟

Timeline
```

都是在描述同一件事。

### 建议优化

合并成一个 Day Header：

```text
Day 1 · 春熙路 / 太古里
3 个地点 · 2 顿饭 · 移动约 50 分钟
```

下面直接：

```text
地图
↓
Timeline
```

删除额外的“今天的动线”和 Day Intent 卡片。

## 7. 桌面端右侧栏建议 Sticky

### 问题

当前桌面布局是：

```text
左侧：地图 + Timeline
右侧：酒店 + 美食 + 交通 + 来源 + Warning
```

随着左侧 Timeline 很长，右边重要摘要会离开视野。

### 建议优化

右侧栏使用 Sticky，并只保留：

```text
住宿
今日美食
预算摘要
关键 Warning
```

来源、Audit 等技术信息不要继续占右栏主位置。

## 8. 可信度 / 来源 / 规划依据太靠前

### 问题

当前顶部存在：

```text
可信度卡片
查看全部来源
规划依据
```

这些属于：

```text
为什么系统这么安排？
```

而不是用户第一眼最关心的旅行信息。

### 建议优化

收拢成一个入口：

```text
为什么这样安排？
```

打开后再展示：

```text
数据来源
Evidence
可信度
规划依据
Provider
查询时间
```

只有低可信、降级、未验证路线等异常情况才主动在主界面提示。

## 9. 字号整体偏小

### 问题

页面大量使用：

```text
text-xs
text-[11px]
text-[10px]
```

信息很多时会显得很密、很碎。

### 建议优化

统一层级：

```text
页面主标题      20~24px
Section 标题    16px
核心正文        14px
辅助信息        12~13px
真正 Metadata   11px
```

11px 只用于查询时间、状态、Source 等次要信息。

## 10. 行程编号不应该占主界面

### 问题

当前顶部显示：

```text
真实查询结果 · 行程编号 tp-...
```

Run ID 对开发有用，对普通用户价值很低。

### 建议优化

顶部只显示：

```text
真实数据规划 ✓
```

Run ID 放到：

```text
更多
→ 行程信息
→ 行程编号
→ 数据来源
→ Audit
```

## 11. 地图选中地点后显示经纬度没有用户价值

### 问题

当前地图选中地点后展示经纬度。

### 建议优化

改成旅行信息：

```text
杜甫草堂

14:00 到达
预计停留 2 小时
距上一站约 18 分钟
武侯区 · 青华路37号
```

经纬度放 Debug / Audit 中。

## 13. 推荐开发优先级

### P0

```text
1. Day Tabs 移到地图 + Timeline 上方
2. 删除重复 Summary / Day Intent / 动线信息
3. 重新调整第一屏层级
4. 地图选中信息改成旅行信息，不显示经纬度
```

### P1

```text
5. 接真实高德地图
6. 右侧栏 Sticky
7. 可信度 / 来源 / 规划依据下沉
8. 统一字体层级，减少 10px / 11px 小字
```

### P2

```text
9. 地图与 Timeline 双向联动
10. 更自然的修改行程入口
11. 移动端 Day / Map / Timeline 切换体验
```

## 14. 验收标准

改完以后应满足：

- 用户 3 秒内能看懂：去哪、几天、住哪里、今天怎么玩、预算多少。
- Day 切换一次后，地图、行程、美食、当天摘要全部同步变化。
- 同一个酒店 / 交通 / 预算只存在一个完整详情，其余位置只展示短摘要。
- 地图展示真实道路、POI、路线、酒店和当天动线。
- Source、Audit、Run ID、经纬度、Provider 默认不占主视觉。

## 15. 最终目标

当前结果页已经不缺功能，下一步重点不应该继续增加卡片。

核心应该从：

```text
还能展示什么？
```

变成：

```text
哪些信息可以删掉？
什么才是用户最想第一眼看到的？
```

核心原则：

> **让地图 + Day 时间线成为页面绝对主角；删掉重复信息，把来源、可信度和技术数据放到第二层。**
